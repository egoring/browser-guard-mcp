# browser-guard-mcp 설계서

에이전트에게 브라우저를 주되, 사고가 불가능하게 만드는 MCP 서버의 설계 문서.
코드와 1:1로 대응한다 — 각 절에 해당 파일을 명시했다.

> **쉽게 말하면** — AI에게 "브라우저를 조작하는 손"을 달아주되, 그 손에 장갑(읽기 전용)과 출입증(도메인 허용목록)을 채우고, 모든 행동을 블랙박스(감사 로그)에 남긴다.

---

## 1. 문제 정의

LLM 에이전트에 브라우저를 그대로 열어주면 세 가지 사고가 가능하다.

1. **의도 밖 이동** — 지시를 오해하고 임의 사이트·로컬 파일을 연다.
2. **의도 밖 조작** — 실수로 버튼을 누르거나 폼을 제출한다.
3. **추적 불가** — 사고가 나도 에이전트가 무엇을 했는지 알 수 없다.

설계 원칙은 sql-guard-mcp와 동일하다: **모델이 조심하길 기대하지 말고, 부주의가 불가능하게 만들 것. 모든 거절 메시지는 에이전트에게 다음 행동을 알려줄 것.**

## 2. 가드 계층 (`guard.py`)

| 계층 | 막는 것 | 방법 |
|---|---|---|
| 도메인 허용목록 | 의도 밖 사이트 이동 | http(s) URL의 호스트를 `BROWSERGUARD_ALLOWED_DOMAINS`와 대조. 서브도메인은 허용하되, 끝만 비슷한 위장 도메인(`books.toscrape.com.attacker.io`)은 차단 |
| 로컬 파일 격리 | 임의 파일 열람 (`/etc/passwd` 등) | file·로컬 경로는 `resolve()` 후 동봉 `demo_site/` 내부인지 검증 — 경로 탈출(`../`) 불가 |
| 읽기 전용 모드 | 의도 밖 클릭·입력 | **기본값이 읽기 전용** — 끄려면 `BROWSERGUARD_READ_ONLY=false`를 명시해야 한다 (안전 기본값 원칙) |
| 텍스트 상한 | 컨텍스트 윈도 범람 | `get_text` 반환을 `max_text_chars`에서 자르고 `truncated` 표시 |
| 세션 수준 차단 (`browser.py`) | 다운로드·팝업 | `accept_downloads=False`, 새 탭·팝업은 열리는 즉시 닫음 — 도구 계층이 뚫려도 세션이 막는다 |

가드 검증은 **브라우저 호출 전에** 일어난다. 차단된 요청은 Playwright에 도달조차 하지 않는다 (테스트 `test_navigate_blocked_domain_never_reaches_browser`가 이를 검증).

## 3. 감사 로그 (`audit.py`)

모든 액션을 `{시각, 동작, 대상, 허용 여부, 상세}`로 기록한다. 핵심 결정 두 가지.

- **차단된 시도도 기록한다.** "에이전트가 google.com에 가려 했다"는 사실 자체가 중요한 관측 신호다 — 프롬프트 인젝션·지시 오해의 흔적이 여기 남는다.
- **에이전트 자신도 열람 가능**(`browser_audit_log` 도구). 사용자가 "방금 뭐 했어?"라고 물으면 에이전트가 자기 행동 기록을 근거로 답할 수 있다.

## 4. 도구 목록 (`server.py`)

| 도구 | 동작 | 가드 |
|---|---|---|
| `browser_navigate(url)` | 이동 → 최종 URL·제목 | 허용목록·로컬 격리 |
| `browser_get_text()` | 본문 텍스트 추출 | 텍스트 상한 |
| `browser_click(selector)` | 요소 클릭 | 읽기 전용 모드 |
| `browser_fill(selector, value)` | 입력 채우기 | 읽기 전용 모드 |
| `browser_screenshot()` | PNG 저장 → 경로 | — |
| `browser_guard_status()` | 현재 가드 설정 조회 | — |
| `browser_audit_log(limit)` | 행동 기록 최신순 조회 | — |

에러는 예외가 아니라 `{"error": "..."}`로 돌려준다 — MCP 클라이언트(에이전트)가 읽고 스스로 설명·재시도하게 하기 위함이다.

## 5. 브라우저 세션 (`browser.py`)

- headless Chromium 1개, **지연 생성** — 서버 기동 시엔 브라우저를 띄우지 않는다.
- 탭은 항상 하나 — 팝업·새 탭은 `context.on("page", close)`로 즉시 닫아 상태를 단순하게 유지.
- Playwright 미설치 시 설치 명령을 담은 에러로 안내 (행동 가능한 에러 원칙).

## 6. 테스트 전략 (`tests/`)

실제 브라우저 없이 검증한다 — 가드는 순수 함수, 서버는 모의 세션 주입.

- `test_guard.py` (11건): 허용/서브도메인/위장 도메인/로컬 격리/경로 탈출/읽기 전용/상한/환경 변수 파싱
- `test_server.py` (8건): 차단 시 브라우저 미호출, 감사 로그 ok·차단 기록, 쓰기 모드 전환, 상한 적용, 상태 조회

적대적 케이스가 절반이다 — 가드 저장소의 테스트는 "되는 것"보다 "안 되는 것"의 증명이 본체다.

## 7. 데모 시나리오 (`demo_site/`)

동봉된 가짜 쇼핑몰 한 페이지로 세 장면을 시연한다.

1. "데모 상점 열어서 3만 원 이하 상품 알려줘" → navigate + get_text → 정상 답변
2. "무선 마우스 주문해줘" → click 거절(읽기 전용) → 에이전트가 이유를 설명
3. "구글에서 검색해봐" → navigate 거절(허용목록) → 허용 목록 안내

외부 인터넷이 필요 없어 CI·오프라인에서도 같은 시나리오가 재현된다.

## 8. 한계와 확장

- 세션이 프로세스당 1개 — 병렬 작업은 범위 밖 (단순성 우선).
- 셀렉터 기반 조작만 — 좌표 클릭·키 입력 시뮬레이션은 v2 후보.
- 확장 방향: 도메인별 차등 권한(이 사이트는 읽기, 저 사이트는 클릭까지), 감사 로그 파일 영속화, 액션당 승인 콜백(human-in-the-loop).
